# Model-free learning runtime (task 04)

Task 04 adds lessons 04–05 to the existing six-stage course. Production remains static, browser-only vanilla ES modules. Training runs in one native module Web Worker; Chart.js 4.5.1 renders locally computed data. No learner calls a remote service or the environment's model API.

Task-05 extends the same runtime and backup namespace to lessons 06–07; see [approximation and planning](APPROXIMATION_PLANNING.md). The maps and episode-budget comparisons described below are specifically lessons 04–05.

## Scientific contracts

`src/agents/tabular.js` declares capabilities and implements four sampled learners. First-visit Monte Carlo and TD(0) evaluate the configured **right** or **uniform** policy, independent of their value estimates. MC updates the earliest occurrence of each state from a genuinely terminated episode using its full discounted suffix return and sample-average step size `1/N`. Capped/interrupted episodes increment a skipped counter and supply no complete-return update. Frequent caps can bias the retained sample; this limitation is taught explicitly. TD(0) updates per transition.

SARSA uses the actual next behavior action selected before the current update. The saved pending decision is executed on the next step, even after a collision. Q-learning uses the next-state maximum. Both control methods use constant epsilon-greedy training, uniform exploration over four actions, and tie order up/right/down/left. The recorded branch is determined by the exploration draw, even when exploration selects the greedy action. True termination zeroes continuation; an external timeout retains the TD/SARSA/Q bootstrap. At a timeout SARSA's next action is selected for the target but is not executed in that capped episode.

`TrainingRun` uses the task-02 `IslandEnvironment`; there is no second transition implementation. The supported task maps have fully observed position state and no enabled inventory, battery or task-horizon variables. The prediction corridor has slip 0.2, cost −1 and goal-entry reward 5. The cliff variant is 6×4: action cost −1 and additional hazard cost −20. Hazards neither teleport nor terminate; the goal does. These are declared original lesson scenarios, not a claim of reproducing a specific textbook cliff benchmark. Gamma is restricted to [0,0.99].

Learned parameters, visits and traces start empty/zero. The control “value” overlay is explicitly `max Q`, not an estimate of the epsilon-greedy policy's V. Other overlays show four actual Q values, the specified/greedy policy, action visit counts, and the last TD or complete-return error. Unvisited arrows follow the declared tie rule. DOM grids/tables and textual traces accompany Canvas. Why this action? formats selection-time values/probabilities/draws and pre-update quantities; it does not infer a decision after learning changes the tables.

## Worker, controls and reproducibility

- `training.worker.js` owns `WorkerHost`; `TrainingCoordinator` is the sole UI owner. Requests contain protocol 1, run ID, increasing command ID and immutable configuration hash. Responses additionally have monotonic sequence IDs. Old run/configuration/reordered responses are ignored.
- `Step` accepts one sample/update. `Episode` finishes one current/new rollout. `Train batch` completes 1–1,000 episodes subject to the 2,000-row run limit. Worker chunks yield after at most 32 transitions or approximately 8 ms; progress is limited to ten messages per second. Command acknowledgments are separate from completion events.
- `Pause` retains the exact pending budget, RNG, MC episode buffer and SARSA action. `Resume` continues it. `Cancel` invalidates queued chunks and preserves actual learned parameters/results. It does not relabel a partial job as completed. A route change disposes the worker; a stage change cancels active work.
- `Reset episode` preserves tables and historical results; a partially observed episode is labeled interrupted and MC omits its return. `Reset learning` requests confirmation, starts a fresh experiment version, zeroes tables, and separates curves. Applying scientific settings also creates a new version. Display speed changes do neither.
- Environment and action RNGs use separate versioned xorshift32 streams. Episode seed namespaces are `training/environment/<episode>` and `training/agent/<episode>`. Independent-agent comparison roots use `independent-training/<replicate>`; held-out evaluation roots use `held-out-evaluation/<replicate>` and action substreams use `evaluation/actions`. Rendering consumes no simulation randomness.
- Checkpoints include immutable configuration/scenario, environment serialization, both RNG states, learned parameters, current episode samples, pending SARSA decision, counters, episode rows and last update trace. Validation checks map/state/action compatibility, finite bounded tables, counters, and replays the current episode. It does not authenticate claimed student work or recompute every historical training update.
- Command completion waits for checkpoint persistence. Abruptly leaving during training retains the last delivered checkpoint; work since the most recent bounded progress message may be discarded. Refresh resumes that consistent checkpoint, not a background job. An interrupted independent comparison is labeled cancelled and retains its finished replicates.

## Evaluation, comparisons and metrics

Evaluation clones parameters and uses a separate environment/action RNG. It has no learner update API. Prediction evaluation follows the same fixed policy; control evaluation uses greedy actions with epsilon 0 and the fixed tie order. Five held-out episodes are separate from all training data. Repeating Evaluate uses the same recorded suite for reproducibility, not five newly randomized seeds each time. Training tables, visits, RNGs, counters and episode position remain unchanged.

Comparisons train five independent agents per method, with paired root seed lists and identical map/configuration/budgets. Shared seeds do not imply identical trajectories. A known-model reference computes prediction RMSE only for the exact corridor and specified policy; model access belongs to the reference evaluator, never the sampled learner. Control comparisons use each agent's mean frozen-evaluation return. The displayed mean and min/max are across five independent agents; they are observed ranges, not confidence intervals. These are known-map comparisons only. There is no transfer/zero-shot score.

Each raw episode records reward sum, discounted reward sum from its first action, accepted transition count, success, genuine termination, external truncation, hazard-entry count and seeds; training additionally records episode index, interruptions and numerical update count. Success means goal termination. Active worker compute time sums measured chunk work, excludes pauses/messaging/rendering, and resets at checkpoint restoration. Per-replicate training/evaluation compute times are saved separately. Episode budgets and interaction/update counts are always recorded.

Blue training curves are raw observed reward sums (including capped rollouts). Rose is a trailing arithmetic mean of the current and up to six preceding completed/capped rows. Interrupted rows are omitted from the plot but retained in exports. Frozen evaluation bars are raw, unsmoothed, and separate. The UI shows the most recent 100 raw training rows; export retains all bounded rows. Plots use no interpolation/animation that invents observations. Inspector rounding is presentation only; exported numbers retain JavaScript precision.

## Lesson evidence and local storage

Lessons reuse the course's six stage names. Completion requires an Observe concept check, prediction saved before results, a real rollout with at least one update, two numeric update checks, a finished five-agent-per-method comparison, and a comparison/concept challenge. The winning answer comes from that comparison, including ties. No required reward threshold or universally winning algorithm is assumed. Reflections remain ungraded text. Exploration ahead and Next never grant completion; failed explicit attempts are retained.

`learning-store.js` uses `rl-island:model-free-progress:v1` for lesson evidence and IndexedDB `rl-island-learning-v1/checkpoints` for model checkpoints. The task-03 store/export for lessons 01–03 is preserved. The notebook exposes distinct foundations and learning backup controls. Import previews and explicit replacement are required. Backups are self-reported artifacts, not signed grades. A checksum detects accidental corruption only. Duplicate/unknown fields, invalid versions/tables/provenance, nonfinite numbers and oversized input are rejected before replacement; free text is escaped. Unreadable existing storage is preserved. Quota/unavailable-storage errors retain usable memory state with a visible export warning.

Bounds: four experiment checkpoints, three comparisons, ten standalone evaluations and sixty check attempts per lesson; 2,000 training rows / two million transitions per interactive run; 20–300 episodes per comparison agent; 1–1,000 transitions per rollout; 16 MiB import; 12 MiB serialized-character bound for learning evidence (browser storage quotas may be lower; compact exports remain bounded to 16 MiB). Limits report errors without silent eviction or mixing. This milestone does not provide a UI for pruning archived records; a larger history manager/migrations are future work. Browser refresh must not be relied on for memory-only work.
